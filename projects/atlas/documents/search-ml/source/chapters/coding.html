Frecency: sufficient state and units

At time t, score = Σ wᵢ 2−(t−tᵢ)/h, where h is the positive half-life in the same units as timestamps. Store the score at the last update; decay that score to the new event time before adding the event weight. This works because exponential decay composes across time intervals. A signal of 4 becomes 2 after one half-life and 1 after two. It models temporal preference, not relevance or causality by itself.

MMR and context: diversity is not completeness

Greedy MMR chooses an unselected candidate maximizing λ·cos(query,candidate) − (1−λ)·max cos(candidate,selected). The redundancy term is zero for the first choice. λ=1 prioritizes query similarity; smaller values penalize similar selected evidence. Unit-normalize nonzero vectors and reject invalid shapes. A count/sum task needs complete eligible records or an exact aggregation tool; diverse top-k evidence cannot establish the total.

The packing contract counts the entire serialized candidate context, including passage IDs and separators, with a caller-supplied tokenizer. Word splitting is a test fixture only: 100 CJK characters are not generally one model token. Reserve instructions, tool schema, history, and output separately. Skipping one oversized passage permits later smaller ones but may omit indispensable evidence; inspect coverage rather than equating budget compliance with answerability.

Stable selection and bounded scan workspace

Use a partition threshold to find the boundary score, take all strictly higher scores and only enough earliest boundary ties, then sort the selected k items by score and input order. Sorting every tied input is unnecessary. The reference uses O(n+k log(k+1)) selection work and O(n) score storage. Its blockwise scan is exact for the reconstructed quantized score; compare its result to an independently computed score vector.

1. Immutable rectangle sums

Define P[r,c] as the sum of matrix entries in rows [0,r) and columns [0,c). Padding the top row and left column with zeros makes empty prefixes legal. To build P[r+1,c+1], add the new cell, the prefix above, and the prefix to its left, then subtract their overlap. An inclusive query [r1:r2,c1:c2] uses the same inclusion-exclusion identity:

Preprocessing and storage are O(RC); each query is O(1). The implementation validates rectangular input and query bounds. An empty matrix can be constructed but has no valid rectangle query. The stored prefix is a snapshot: later mutations to the input are not reflected. Frequent updates would call for a different structure, such as a 2D Fenwick tree, rather than silently reusing this contract.

2. Top-k with deterministic ties

Maintain a min-heap of the best k entries seen so far. Its root is the worst retained entry. Use (score,−input_order) as the ordering key so earlier items win ties. A unique sequence number prevents Python from trying to compare arbitrary document IDs on a tie. The invariant is preserved because a new item replaces the root only when its key is better.

@@CODE:top_k@@

For n items and k≥2, selection is O(n log k), followed by O(k log k) output sorting, with O(k) auxiliary space. More uniformly, use O(n log(k+1)+k log(k+1)); k=1 is linear. If k exceeds n, return all items. k=0 returns immediately. Scores must be finite. Duplicate IDs remain separate input occurrences here; deduplication is a separate contract.

3. Stable cross-entropy and one training step

Subtract the maximum logit in each row before exponentiating. This leaves softmax unchanged and avoids exponential overflow for ordinary finite inputs. Compute the loss through log-probabilities, not by taking the logarithm of an already rounded probability. A very unlikely target can underflow to probability zero while its log-probability remains representable.

@@CODE:softmax_ce@@

The gradient has shape B×C. For a linear classifier X∈ℝB×d, W∈ℝd×C, and b∈ℝC, logits=XW+b. Backpropagation yields dW=XᵀdZ+λW and db=ΣbatchdZ. The loss already averages over the batch; dividing again would shrink the gradient incorrectly.

@@CODE:linear_step@@

The included in_batch_loss applies this same CE to QDᵀ/τ and returns gradients for both encoders' output vectors. Its input vectors are not normalized internally. If you add normalization, backpropagate through that operation as well; gradients with respect to normalized vectors are not automatically gradients with respect to the original vectors.

Finite-difference check

For parameter θi, compare the analytic derivative to [L(θ+εei)−L(θ−εei)]/(2ε). Use float64 and a moderate ε such as 10⁻⁶ on a small example. Check absolute and relative error; relative error is unstable when both derivatives are almost zero. Fix randomness and avoid nondifferentiable boundaries. The bundled tests check both logit and embedding gradients.

4. Attention: shapes explain the computation

@@EQ:attention@@

For one head, Q has Lq×dk, K has Lk×dk, and V has Lk×dv. Scores have Lq×Lk; normalize across the key axis for each query. The output is Lq×dv. Scaling by √dk controls dot-product magnitude under the usual independent-component variance intuition. Multiple heads learn separate projections, then concatenate and project their outputs. [Transformer paper]

For a batch of self-attention with B=2, L=5, model width 12 and h=3, each head width is 4. Q/K/V can be arranged as [2,3,5,4]; scores are [2,3,5,5]; concatenated outputs are [2,5,12]. Causal masking disallows future keys; padding masks remove padded keys. In the equation, M is 0 for an allowed key and −∞ for a blocked key. Mask before softmax. An all-masked row needs an explicit convention: the teaching implementation rejects it.

@@CODE:self_attention@@

The implementation omits learned projections, multi-head reshaping, dropout, residuals, and normalization so the core operation stays visible. Directly materialized attention scores use O(L²) memory per head and O(L²d) arithmetic for self-attention; projection work adds O(Ld²). Optimized kernels can change memory behavior without eliminating the dense pairwise arithmetic. Increasing head count at fixed total width does not multiply every cost by head count.

5. Optimization and generalization: diagnose before changing knobs

ObservationCandidate causesDiscriminating check / response
Training and validation losses both highUnderfitting, optimization failure, bad labels, implementation bugOverfit a tiny batch first; inspect gradients and data before adding capacity
Training loss falls, validation worsensOverfitting or train/validation distribution mismatchCheck splits and slices; try regularization, early stopping, or more representative data
Loss oscillates or divergesLearning rate too large, extreme inputs, gradient explosionInspect norms and nonfinite values; lower LR, check scaling, consider clipping
Loss decreases very slowlySmall LR, poor conditioning, bad initializationShort LR sweep; inspect update-to-weight ratios and activation distributions
Train/eval behavior differs sharplyDropout/normalization modes, feature mismatchCompare identical examples in the correct modes and with matching transforms

A minibatch gradient estimates the empirical full-data gradient when sampling and weighting match the objective. Larger batches reduce sampling noise but change optimization dynamics and memory use; learning-rate scaling is a tuning heuristic. Warmup increases LR gradually to limit unstable initial updates; decay reduces step size later. Neither repairs incorrect labels or leakage.

L2 penalizes large weights in the objective. For plain SGD, it corresponds to multiplicative weight shrinkage with the matching coefficient. With adaptive optimizers, adding an L2 gradient and applying decoupled weight decay generally differ. [Decoupled weight decay]

Batch normalization uses batch statistics per feature (often including spatial axes in convolutional settings) during training and typically running statistics at inference. Layer normalization normalizes selected features within each example/token and does not depend on other batch examples. Both learn scale/shift parameters; neither is a general data-leakage defense. Small or shifting batches can make BatchNorm behavior tricky. [BatchNorm] [LayerNorm]

Optional five-minute classical ML refresher

Bagging trains models on resampled data and averages them, often reducing variance when their errors are not perfectly correlated. Gradient boosting adds weak learners that fit loss-reducing directions, typically negative gradients. Trees are strong baselines for heterogeneous tabular features; neural encoders are useful for learned representations of text and other unstructured inputs. Compare under the same split and deployment constraints.

K-means minimizes squared Euclidean distance to assigned centroids through alternating assignment and mean updates. A Gaussian mixture uses soft component responsibilities and covariance assumptions; EM alternates responsibility estimation and parameter updates. Initialization and local optima matter in both. These are optional refreshers, not a reason to broaden this guide into an algorithm survey.
