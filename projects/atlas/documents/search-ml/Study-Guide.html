01 · Search

Search technologies

Indexes, candidate generation, and reranking

A retrieval system spends a small computation budget deciding which documents deserve a larger one. Study the candidate set, scoring function, and execution algorithm as separate choices.

After this chapter: trace a query through lexical and vector indexes; choose a candidate budget; identify whether a quality loss comes from representation, approximate search, or reranking.

1. Lexical retrieval: representation and execution

Suppose the query is red running shoes. A lexical index maps each analyzed term to a sorted posting list of document IDs, usually with term frequency and sometimes positions. The document text travels through a tokenizer and normalization pipeline before indexing; query analysis must remain compatible. Indexing is the expensive preparation that makes repeated lookup cheap.

The union produces D1–D4; the intersection produces only D1. Either is a legitimate matching policy. OR-style matching permits partial evidence and ranks it; AND-style matching treats each term as a hard constraint. A missing term contributes zero to an additive term score, but a query engine may separately impose required terms or a minimum match count. Do not confuse that matching policy with the score formula.

Using D2 for a query about running shoes may be useful despite the absent color term. If the user explicitly filters color=red, the same absence can disqualify it. A query term and a structured constraint have different semantics. Phrase matching also needs order or positions: having all words does not establish a phrase match.

Low IDF reduces a common term's score contribution, but reading a huge posting list still costs work. Stop-word removal trades retrieval cost against meaning. It can damage phrases, negation, and entity names; punctuation removal can merge distinct identifiers. Prefer analyzer choices tested on actual query slices rather than a universal deletion rule.

Personal-search analysis, prefixes, and updates

Normalize query and index text with the same versioned analyzer. Unicode normalization and case folding help compatible forms match; accent folding and transliteration can also create collisions. Preserve original strings for display and exact identity. Whitespace splitting is inadequate for languages without word spaces. Evaluate CJK segmentation, mixed-script names, identifiers, emoji, and locale-specific case behavior separately. The practice tokenizer is intentionally a small English-like baseline.

For an unfinished last token, combine completed-token matching with a prefix lookup. A trie caches completions at prefix nodes; an FST can compact a largely static vocabulary; edge n-grams trade index size for ordinary posting lookup. Cached top-k suggestions remain correct only under the update contract: arbitrary score decreases or deletions may require rebuilding affected caches. Prefix matching alone does not repair misspellings.

Fuzzy matching can use edit-distance automata over a term dictionary, deletion-variant lookup followed by exact distance checks, or a BK-tree exploiting metric distances. Restrict edit radius, minimum query length, and candidate count to control ambiguity and cost. A deletion index generates candidates, not proof of a valid match. Distinguish candidate-ranking quality from edit-distance correctness; short queries are particularly ambiguous.

Incremental indexing appends new segments and masks obsolete documents with tombstones, then compacts later. Query results must observe the intended document version and permissions even before compaction. Replacement updates also change corpus length and document-frequency statistics. A freshly added document absent from a stale embedding index should still have a lexical path.

For title, body, and filename fields, BM25F combines weighted length-normalized field frequencies for each term before saturation. Summing independently saturated BM25 field scores is another useful model, with different behavior; call it field-score fusion rather than assuming the formulas coincide. Tune field weights on held-out slices and avoid treating filenames or entity fields as ordinary prose without testing.

Let N=100, df=10, k1=1.2, b=0.75, and |d|=avgdl. Then IDF=ln(1+90.5/10.5)≈2.264. For f=1, the frequency factor is 1; for f=2 it is 4.4/3.2=1.375; for f=10 it is 22/11.2≈1.964. Ten repetitions do not produce ten times the score.

At f=2, doubling document length increases the denominator from 3.2 to 4.1, reducing the frequency factor to about 1.073. This compensates for a longer document having more opportunities to contain the term. It is a modeling assumption, not a proof that shorter documents are more relevant.

3. Efficient top-k: safe skipping instead of scoring every match

A direct implementation accumulates term contributions across every matching document and retains the best k in a min-heap. The heap root is the current admission threshold, θ, once the heap is full. This is already much cheaper than scanning all document text, but common query terms can still create huge candidate sets.

WAND uses upper bounds on additive term contributions. Posting iterators are ordered by current document ID; cumulative bounds identify a pivot at which a document could beat θ. Iterators can skip IDs proven unable to compete, and promising documents receive full scoring. Block-level bounds tighten this idea. Exact top-k preservation requires valid bounds for the actual score, a conservative threshold, and correct tie handling. A deployed operator can also use approximation settings. [WAND paper] [Vespa implementation caveats]

Bound exercise: a region's maximum possible contributions are 0.7, 1.1, and 0.8. Their sum is 2.6. If θ=3.0, skip that region; no exact score there can win. If θ=2.0, the bound cannot decide: score or tighten the bound. A bound above θ does not mean the document is relevant. Before collecting k documents, use a threshold that cannot prematurely discard needed results.

This is different from intersecting posting lists: WAND can retain high-scoring partial matches. It is also different from applying a costly neural reranker to every lexical match. A pruning guarantee under BM25 does not guarantee preservation of the best documents under an unrelated downstream neural score.

4. Dense retrieval and the two meanings of “inverted”

A bi-encoder computes a query vector u(q) and a document vector v(d), often scoring their dot product. Document vectors are precomputed; one query embedding can be compared against many documents. Unit normalization turns dot product into cosine similarity, removing vector norm as a ranking signal. Decide deliberately whether norm should carry information.

Flat search evaluates all vectors and provides an exact reference for the chosen metric. Product quantization compresses vectors and adds distance approximation; it can be combined with IVF. [Faiss index reference]

For one million 768-dimensional float32 vectors, raw vectors alone occupy 3.072 GB (about 2.86 GiB). IDs, graph edges, metadata, replicas, and working memory are extra. Index choice is a capacity decision as well as an algorithm decision.

Separate two recalls. ANN recall@k measures agreement with exact vector top-k. Relevance recall@k measures recovery of relevant documents. Perfect ANN recall cannot repair a poor embedding; a strong embedding cannot retrieve a neighbor excluded by an overly narrow ANN search.

5. Hybrid retrieval and reranking

Lexical retrieval can preserve exact names, rare identifiers, and explicit wording; dense retrieval can connect paraphrases. Neither advantage is universal. For a query such as expense policy for rides home late, lexical matching might find an exact policy title while dense retrieval finds a paragraph phrased as “transportation after extended working hours.” Union the candidates by stable document ID, retain their source scores, and measure whether each channel adds unique relevant results.

A simple rank-based fusion baseline is reciprocal rank fusion (RRF): each channel contributes 1/(c+rank) when a document appears; missing documents contribute zero. It avoids adding incompatible raw scores, though it discards score magnitudes. Choose the constant and channel weights on validation data. Fusion is a candidate-ordering baseline; a learned ranker can use channel identity, lexical score, semantic score, and context.

With c=60, lexical results [A,B,C] and dense results [B,D,A] give A≈0.03227, B≈0.03252, C≈0.01587, D≈0.01613. B narrowly wins because it ranks highly in both channels. This is an illustration, not evidence that c=60 is optimal.

A cross-encoder jointly processes query and document, enabling token interactions that independent embeddings cannot express directly. The cost is query-dependent computation per candidate. Apply it to a bounded shortlist, benchmark batching and sequence length, and retain a cheap fallback. For long documents, passage selection changes both cost and the evidence the ranker can see.

Budget thought experiment: lexical returns 200 and dense returns 200, overlapping on 80 IDs, so their union has 320. If only 50 can receive expensive reranking, evaluate whether the cheap ranker preserves relevant candidates in those 50. Moving from 200 to 400 dense candidates may not help if the same cheap stage removes the new useful documents.

3. Contrastive learning is a task construction; InfoNCE uses cross-entropy

Encode one query and a candidate set containing its positive document plus negatives. Define candidate logits s(q,dj)/τ. The label is the positive candidate's index. The resulting objective is ordinary categorical cross-entropy over that candidate set:

The gradient on a negative score is pj/τ; on the positive it is (p+−1)/τ. Confusing negatives receive larger repulsive updates. Temperature changes both probability sharpness and the gradient scale; it is not merely a display-time rescaling.

InfoNCE is a contrastive objective with this form; the CPC paper develops a density-ratio interpretation under its sampling setup. That interpretation relies on how positives and negatives are drawn. “Contrastive loss” also includes objectives such as margin-based triplet losses, so not every contrastive objective is softmax cross-entropy. [CPC / InfoNCE]

Why the negative sampler changes the task

Suppose q is “jaguar charging issue.” Random animal documents are easy negatives; nearby automobile support articles force the model to distinguish vehicle relevance and intent. But a second valid troubleshooting article may be a false negative. Hard-negative mining should improve discrimination without routinely penalizing valid alternatives.

For scores [2,1,0] and τ=1, the positive loss is 0.4076. At τ=0.5 the logits become [4,2,0], loss≈0.1429. This particular example becomes easier because the positive already leads. If a negative leads, reducing τ increases the penalty. Smaller temperature is not uniformly better.

With a batch of B matched query-document pairs, Q and D have shape B×d and S=QDᵀ/τ has shape B×B. The diagonal supplies positive indices and the other columns act as negatives. This assumes off-diagonal pairs are usable negatives. Duplicate documents and multiple relevant documents violate the simplest interpretation. Use masking, a multi-positive objective, or better supervision as appropriate. Sampling corrections are needed if the intended objective is an approximation to a full-corpus softmax; an uncorrected sampled objective need not estimate that same distribution.

Distillation connection: minimize CE(pteacher,pstudent) or KL(pteacher‖pstudent); for a fixed teacher, they differ by the teacher entropy, which is constant in student parameters. At temperature T, derivatives with respect to student raw logits carry 1/T; conventional T² scaling compensates for approximate gradient shrinkage at high T. It is a training convention, not a universal mathematical requirement. [Distillation paper]

With exactly one positive and one negative, the contrastive loss reduces to log(1+exp((s−−s+)/τ)). Thus a familiar pairwise logistic objective is a two-candidate softmax loss. This algebra is useful because it connects an implementation to its assumptions.

“Listwise” alone does not ensure diversity or coverage. If the utility rewards complementary evidence, the training target or objective must encode it. Metric-weighted pairwise updates, such as weighting swaps by their effect on NDCG, offer another route. Model family and loss family are separate: a tree ranker is not synonymous with one particular target or evaluation metric.

5. Metrics: declare the unit, labels, and denominator

Recall@k needs a relevant-document set. With incomplete judgments, report recall over known positives and judging coverage; do not label it true corpus recall. MRR uses the reciprocal rank of the first relevant result, so later useful results do not improve that query's score. NDCG supports graded relevance and position discounting:

IDCG is the DCG of an ideal ordering under the declared judging universe and cutoff. Declare what happens when IDCG=0; exclusion and zero are different aggregation conventions. Average per query or per user according to the evaluation goal rather than accidentally weighting by the number of documents. [IR evaluation reference]

Worked example: retrieved grades [0,2,1,0,3] use gains [0,3,1,0,7]. DCG@5=3/log₂3+1/log₂4+7/log₂6≈5.100. Ideal grades [3,2,1,0,0] give IDCG≈9.393, so NDCG≈0.543. With any positive grade relevant, reciprocal rank=1/2. If one of the zeros is actually unjudged, this calculation is conditional on an explicit zero-imputation convention; it does not establish that document's irrelevance.

AUC is the probability that a randomly selected positive scores higher than a randomly selected negative, with half credit for ties. It evaluates pair ordering rather than probability calibration. Pooling examples across unrelated queries can reward between-query offsets, so inspect the evaluation population. For rare positives, also examine precision-recall behavior and operating points. A monotonic score transformation can preserve ranking and AUC while making probability calibration much worse.

In RAG or agent retrieval, success may require several complementary sources. Add evidence coverage, duplicate rate, and downstream task success measured with a fixed generator and budget. Ranking position can still matter because of truncation and the consumer's attention behavior. Switching from human search to agent consumption does not automatically make order irrelevant.

6. Position bias and counterfactual claims

A simple examination model writes click=examination×relevance, with the necessary conditional-independence assumptions. Examination propensities can support inverse-propensity weighting of observed feedback. This is not equivalent to weighting every unclicked result as irrelevant, nor does a position-only propensity fix trust bias, selection bias, or all interactions. Estimated propensities and very large weights create additional error and variance. [Unbiased learning to rank]

If a binary action is logged with μ=0.25 and the target selects it with π=0.5, its weight is 2. A reward of 1 contributes 2/n to the estimate. If μ=0, no finite weight can recover the missing outcome. Weight clipping can reduce variance but generally introduces bias.

Scoring a candidate model on a long-term holdout is useful predictive evaluation, but it does not reveal outcomes caused by the candidate's unexecuted decisions. A randomized online comparison can estimate the effect of actually serving different policies under its experimental design. Repeatedly tuning against a holdout also makes it less independent, even if the holdout's serving policy never changes.

03 · System

Two on-device search designs

Data, training, serving, and measurement

Two search systems share an index but serve different consumers: a person choosing a result while typing, and a model assembling evidence for an answer. Their budgets, ranking objectives, and failure modes should differ.

Core reading. Reconstruct both designs, including their update and learning paths. For each decision, identify the quality benefit, the memory/latency/energy cost, and the data required to evaluate it.

1. Scope, assumptions, and public platform examples

On-device search is a useful design scenario for studying retrieval under privacy, resource, and freshness constraints. Assume offline operation, permissioned personal content, a changing corpus, and constrained memory/energy. The numbers below are teaching inputs that should be replaced with measurements on a specified device.

Apple's public Core Spotlight material establishes a private on-device index, semantic queries, item engagement signals, and reindexing support. Its WWDC26 session describes a SpotlightSearchTool, full-item hydration through an index delegate, scoped guidance profiles, and computation stages. These are useful examples of interfaces and constraints; they do not establish the internal implementation of any particular product. [Core Spotlight] [Search tool]

2. Design A: interactive, as-you-type personal search

Example: a user types “pho,” then “phot,” looking for Photos or a recent photo-related note. Assume 100,000 indexed text-bearing items across authorized sources, plus a small inventory of apps/settings. The first useful results should appear quickly; a slower semantic refinement can arrive later. Define a responsiveness target on the actual device rather than assuming an encoder and scan finish in a fixed number of milliseconds.

Incremental filtering needs a completeness argument

Suppose the top two completions for “pho” are phone and photo; photon ranks third. Filtering those two for “phot” returns only photo, although photon belongs in the new top two. Reuse a complete prefix range, requery the prefix structure, or refill when cached coverage is insufficient. Even a complete matching set may require rescoring as query-dependent features change.

Ranking signals: title/app exact match, last-token prefix match, field-aware lexical score, fuzzy distance, semantic score where available, recency, decayed usage, and query-prefix affinity. A missing semantic score should be represented as “channel did not run,” not automatically zero similarity. Usage affinity can be valuable for navigation, but its strength must be established by ablation and it can create feedback lock-in.

Frecency with half-life H gives a use at age Δt weight 2−Δt/H. Store a score and its timestamp; before adding a use, decay the stored score to the new time and add one. This costs O(1) per update without retaining every event. The frecency drill makes the time invariant explicit.

Cross-source ranking and section allocation

App-launch, mail, file, and contact scores may have incompatible scales and outcome definitions. First choose a common utility and comparable exposure context. Calibration can map scores to an outcome rate under the data distribution used for calibration; it cannot turn biased placement logs into P(engagement if shown at the top) without suitable exposure data or assumptions. Randomized/interleaved exposure can help identify placement effects.

A baseline can use a global ranker with source indicators and query features, plus eligibility, deduplication, and section caps. Alternatively use source rankers and validated calibration. Top Hit thresholds trade coverage against error cost. Evaluate the page as a whole: moving a section changes both its visibility and competitors' exposure. Separate known-item success from exploratory engagement.

3. Design B: retrieval for an on-device assistant

Example: “Which hikes did I do with Alex last month, and how far did I go?” The system needs correct identity resolution, date boundaries, item coverage, and arithmetic. A list of individually relevant snippets may still be insufficient to compute the total.

  1. Determine whether retrieval is needed. Personal-data questions need authorized sources; general knowledge may not. Ambiguous requests can need clarification.
  2. Generate and validate a structured request. Represent text, date range, people IDs, item types, aggregation, and limits. Resolve timezone/date arithmetic in deterministic code; a name such as Alex still requires disambiguation.
  3. Retrieve eligible evidence. Apply hard metadata/permission constraints, then lexical and semantic retrieval as appropriate. Preserve the query and filter provenance.
  4. Compute over the correct population. Exact count/sum/group operations should use the complete eligible match set, not just the top-k text hits. Return completeness/partial-result status with aggregates.
  5. Select a compact evidence set. Rerank, remove redundant passages, retain complementary evidence, hydrate full items only when needed, and measure serialized tokens.
  6. Answer with references or uncertainty. Validate cited IDs, numeric consistency, and whether the evidence supports the requested conclusion. Bound tool use by remaining latency, tokens, and expected benefit.
Empty results are not proof of absence. An index may be stale or a soft text match too narrow. Diagnose first. Do not silently widen “last month” or replace the requested person. A broader diagnostic query must remain distinguishable from evidence answering the original constraints. Never relax authorization.

In a simple user-level DP construction, each participant's entire contribution is clipped to norm C. For an unweighted sum under add/remove adjacency, its L2 sensitivity is bounded by C; replacement adjacency can require 2C. For a fixed cohort size m and fixed noise multiplier, noise added to the sum is divided by m in the average. Device efficiency

Representation, adapters, caches, and measurement

Device efficiency is a measured budget across representation quality, working memory, latency, energy, and update cost. A smaller checkpoint alone does not establish a faster search experience.

1. Quantized retrieval: define what is exact

For a vector x, choose a positive scale s=max|x|/127, then store q=round(x/s) clipped to [−127,127]. Reconstruct x̂=sq. With round-to-nearest and no clipping beyond the chosen range, each coordinate's error is at most s/2, allowing for floating-point roundoff. Use s=1 for a zero vector. Per-row scales preserve each document's dynamic range; a shared scale supports different kernels but may sacrifice precision for small-magnitude rows.

A float query scored against reconstructed rows uses score(q,d)=sdΣ qjcd,j. Quantizing the query adds its own scale and error. Exhaustively scoring all stored rows is exact for this quantized score, while its ordering can differ from the original float score. HNSW or IVF introduces a further candidate-search approximation. Evaluate float → quantized exhaustive → quantized indexed separately to locate the loss.

Storage and workspace

100,000 vectors × 256 dimensions × 1 byte = 25,600,000 bytes, about 24.4 MiB, plus 400,000 bytes for float32 per-row scales. Float32 vectors alone occupy 102,400,000 bytes, about 97.7 MiB. IDs, metadata, lexical postings, allocator overhead, and index structures are additional.

Casting the complete int8 matrix to int32 per query allocates another 97.7 MiB. The teaching implementation widens 1,024 rows at a time: 1 MiB for the integer block at this width, plus score storage and arithmetic intermediates. It is a correctness reference using NumPy, not evidence of native int8 hardware throughput.

Dot-product error is bounded by Σ|qj||dj−d̂j| when only documents are quantized. Near-tied items can exchange ranks even with small coordinate errors. Report recall against float exact neighbors and task relevance metrics; neither metric alone measures the other's failure. Compare flat scan and ANN on actual corpus sizes and target devices. Include index build/update cost and memory, rather than using a universal corpus-size threshold.

2. Smaller embeddings and model weights

Reducing dimension from 768 to 256 cuts raw vector storage and dense dot-product arithmetic by a factor of three. It does not guarantee the same relevance. Weight quantization reduces model storage and potentially memory traffic. Activation quantization, accumulator precision, scale granularity, outlier handling, and available kernels also determine speed and quality. A reported success for one architecture, dataset, or device is a starting hypothesis for another.

3. LoRA: parameter arithmetic before tuning

For W∈ℝdout×din, freeze W and learn ΔW=(α/r)BA, with A∈ℝr×din and B∈ℝdout×r. The adapter has r(din+dout) parameters instead of dindout. For a 4,096×4,096 projection and r=8, that is 65,536 adapter parameters versus 16,777,216 base parameters: 1/256 as many. This counts one projection only. Optimizer state, gradients, activations, other projections, and precision affect training memory.

Adapter rank controls capacity, not an automatic quality guarantee. Evaluate held-out tool trajectories or task labels, including failure slices. A merge can remove separate adapter matrix operations for a compatible floating-point deployment; merging into quantized weights may require requantization and renewed quality checks. Serving several adapters also changes caching and switching costs. [LoRA paper]

4. KV-cache memory and decoding

For standard autoregressive attention, approximate KV bytes = 2 × layers × batch × cached tokens × KV heads × head dimension × bytes per element. The 2 counts K and V. This excludes weights, activations, allocator fragmentation, padding, and temporary workspace. Grouped-query attention has fewer KV heads than query heads; use the KV count in this formula.

With 32 layers, batch 1, 4,096 cached tokens, 8 KV heads, head width 128, and 2-byte elements, the cache is 536,870,912 bytes = 512 MiB. With 32 KV heads, it is 2 GiB. At 8,192 tokens, both double. Across-layer KV sharing or cache quantization can alter this estimate; use the architecture's actual retained caches and precision rather than counting every nominal layer identically.

Prefill processes the prompt, often exposing substantial parallel compute. Decode produces successive tokens and often stresses weight/cache memory bandwidth at low batch sizes. These are useful tendencies, not universal bottleneck diagnoses. Measure time to first token, token-generation throughput, peak resident memory, and total task latency; a faster decode does not repair expensive retrieval or prompt construction.

Context capacity is runtime/model/version dependent. Query the supported capacity; reserve tool schema, conversation, prompt, output, and a margin before packing evidence. Longer context increases work and cache use and does not ensure the model attends reliably to every passage. The system chapter gives a complete illustrative budget.

Frecency: sufficient state and units

At time t, score = Σ wᵢ 2−(t−tᵢ)/h, where h is the positive half-life in the same units as timestamps. Store the score at the last update; decay that score to the new event time before adding the event weight. This works because exponential decay composes across time intervals. A signal of 4 becomes 2 after one half-life and 1 after two. It models temporal preference, not relevance or causality by itself.

class Frecency:
    """score(item, t) = sum over past uses t_i <= t of 0.5 ** ((t - t_i) / half_life).
    O(1) per record/score by storing (score at last update, last update time):
        s <- s * exp(-lam * (t - t_last)) + 1,   lam = ln 2 / half_life
    Timestamps per item must be non-decreasing."""

    def __init__(self, half_life):
        if not math.isfinite(half_life) or half_life <= 0:
            raise ValueError("half_life must be positive")
        self.lam = math.log(2) / half_life
        self.state = {}  # item -> (score_at_t_last, t_last)

    def record(self, item, t):
        if not math.isfinite(t):
            raise ValueError("finite timestamp required")
        s, t0 = self.state.get(item, (0.0, t))
        if t < t0:
            raise ValueError("out-of-order timestamp")
        self.state[item] = (s * math.exp(-self.lam * (t - t0)) + 1.0, t)

    def score(self, item, t):
        if not math.isfinite(t):
            raise ValueError("finite timestamp required")
        if item not in self.state:
            return 0.0
        s, t0 = self.state[item]
        if t < t0:
            raise ValueError("query time before last use")
        return s * math.exp(-self.lam * (t - t0))

    def top(self, t, k):
        _check_k(k)
        return heapq.nsmallest(k, ((i, self.score(i, t)) for i in self.state),
                               key=lambda x: (-x[1], x[0]))

MMR and context: diversity is not completeness

Greedy MMR chooses an unselected candidate maximizing λ·cos(query,candidate) − (1−λ)·max cos(candidate,selected). The redundancy term is zero for the first choice. λ=1 prioritizes query similarity; smaller values penalize similar selected evidence. Unit-normalize nonzero vectors and reject invalid shapes. A count/sum task needs complete eligible records or an exact aggregation tool; diverse top-k evidence cannot establish the total.

    """Priority-order greedy packing; returns kept IDs, skipping oversized items.

    Requires an explicit token counter for the target model. Candidate contexts
    are serialized as '[ID]\ntext' blocks separated by two newlines, and the
    WHOLE candidate context is counted each time. overhead_tokens optionally
    reserves extra per-item tokens outside that serialization. This budget is
    for evidence only; reserve instructions, history, tools and output first.
    A toy counter may be injected in tests but is not an LLM token guarantee.
    """

    _check_k(overhead_tokens)
    if not callable(count_tokens):
        raise ValueError("provide the target model's token counter")
    _unique_ids([pid for pid, _ in passages])
    kept, blocks = [], []
    for pid, text in passages:
        candidate = blocks + [f"[{pid}]\n{text}"]
        count = count_tokens("\n\n".join(candidate))
        _check_k(count)
        if count + overhead_tokens * len(candidate) <= budget_tokens:
            kept.append(pid)
            blocks = candidate
    return kept

def top_k_indices(scores, k):
    """Finite 1D scores; descending score, then ascending index.
    Partition + a linear boundary-tie scan + sort of only k chosen entries:
    O(n + k log(k+1)) time and O(n) auxiliary memory in this NumPy version.
    """

    scores = np.asarray(scores, dtype=np.float64)
    if scores.ndim != 1 or not np.isfinite(scores).all():
        raise ValueError("finite 1D scores required")

    if k == 0:
        return np.array([], dtype=int)
    threshold = np.partition(scores, len(scores) - k)[len(scores) - k]
    above = np.flatnonzero(scores > threshold)
    tied = np.flatnonzero(scores == threshold)[:k - len(above)]
    chosen = np.concatenate((above, tied))
    return chosen[np.lexsort((chosen, -scores[chosen]))]

1. Immutable rectangle sums

Define P[r,c] as the sum of matrix entries in rows [0,r) and columns [0,c). Padding the top row and left column with zeros makes empty prefixes legal. To build P[r+1,c+1], add the new cell, the prefix above, and the prefix to its left, then subtract their overlap. An inclusive query [r1:r2,c1:c2] uses the same inclusion-exclusion identity:

Preprocessing and storage are O(RC); each query is O(1). The implementation validates rectangular input and query bounds. An empty matrix can be constructed but has no valid rectangle query. The stored prefix is a snapshot: later mutations to the input are not reflected. Frequent updates would call for a different structure, such as a 2D Fenwick tree, rather than silently reusing this contract.

class MatrixSum:
    """Immutable rectangular matrix; inclusive rectangle coordinates."""
    def __init__(self, matrix):
        self.rows = len(matrix)
        self.cols = len(matrix[0]) if self.rows else 0
        if any(len(row) != self.cols for row in matrix):
            raise ValueError("matrix must be rectangular")
        self.prefix = [[0] * (self.cols + 1)
                       for _ in range(self.rows + 1)]
        for r in range(self.rows):
            for c in range(self.cols):
                self.prefix[r + 1][c + 1] = (
                    matrix[r][c] + self.prefix[r][c + 1]
                    + self.prefix[r + 1][c] - self.prefix[r][c]
                )

    def sum(self, r1, c1, r2, c2):
        if not (0 <= r1 <= r2 < self.rows
                and 0 <= c1 <= c2 < self.cols):
            raise ValueError("invalid inclusive rectangle")
        p = self.prefix
        return (p[r2 + 1][c2 + 1] - p[r1][c2 + 1]
                - p[r2 + 1][c1] + p[r1][c1])

2. Top-k with deterministic ties

Maintain a min-heap of the best k entries seen so far. Its root is the worst retained entry. Use (score,−input_order) as the ordering key so earlier items win ties. A unique sequence number prevents Python from trying to compare arbitrary document IDs on a tie. The invariant is preserved because a new item replaces the root only when its key is better.

Code · swipe horizontally to read long lines

def top_k(items, k):
    """Return (ID, finite score) pairs; score descending, earlier ties first.

    Each input occurrence is a candidate. IDs need not be comparable.
    """
    if k < 0:
        raise ValueError("k must be nonnegative")
    if k == 0:
        return []
    heap = []
    for order, (doc_id, score) in enumerate(items):
        if not np.isfinite(score):
            raise ValueError("scores must be finite")
        entry = (score, -order, doc_id)
        if len(heap) < k:
            heapq.heappush(heap, entry)
        elif entry[:2] > heap[0][:2]:
            heapq.heapreplace(heap, entry)
    return [(doc_id, score) for score, _, doc_id
            in sorted(heap, key=lambda e: e[:2], reverse=True)]

For n items and k≥2, selection is O(n log k), followed by O(k log k) output sorting, with O(k) auxiliary space. More uniformly, use O(n log(k+1)+k log(k+1)); k=1 is linear. If k exceeds n, return all items. k=0 returns immediately. Scores must be finite. Duplicate IDs remain separate input occurrences here; deduplication is a separate contract.

3. Stable cross-entropy and one training step

Subtract the maximum logit in each row before exponentiating. This leaves softmax unchanged and avoids exponential overflow for ordinary finite inputs. Compute the loss through log-probabilities, not by taking the logarithm of an already rounded probability. A very unlikely target can underflow to probability zero while its log-probability remains representable.

Code · swipe horizontally to read long lines

def softmax_ce(logits, labels):
    """Mean hard-label CE and dL/dlogits. Finite BxC logits, B>0, C>0."""
    z = np.asarray(logits, dtype=np.float64)
    y = np.asarray(labels)
    if z.ndim != 2 or min(z.shape) == 0 or not np.isfinite(z).all():
        raise ValueError("logits must be a nonempty finite BxC matrix")
    if (y.shape != (z.shape[0],) or y.dtype.kind not in 'iu'
            or (y < 0).any() or (y >= z.shape[1]).any()):
        raise ValueError("one valid integer class index per row required")
    shifted = z - z.max(axis=1, keepdims=True)
    log_probs = shifted - np.log(np.exp(shifted).sum(axis=1, keepdims=True))
    loss = -log_probs[np.arange(len(y)), y].mean()
    grad = np.exp(log_probs)
    grad[np.arange(len(y)), y] -= 1
    grad /= len(y)
    return float(loss), grad

The gradient has shape B×C. For a linear classifier X∈ℝB×d, W∈ℝd×C, and b∈ℝC, logits=XW+b. Backpropagation yields dW=XᵀdZ+λW and db=ΣbatchdZ. The loss already averages over the batch; dividing again would shrink the gradient incorrectly.

def linear_step(x, y, w, b, lr=0.1, l2=0.0):
    """One SGD step; loss includes l2*||w||^2/2, bias unregularized."""
    loss, dz = softmax_ce(x @ w + b, y)
    dw = x.T @ dz + l2 * w
    db = dz.sum(axis=0)
    objective = loss + 0.5 * l2 * np.sum(w * w)
    return float(objective), w - lr * dw, b - lr * db

4. Attention: shapes explain the computation

For one head, Q has Lq×dk, K has Lk×dk, and V has Lk×dv. Scores have Lq×Lk; normalize across the key axis for each query. The output is Lq×dv. Scaling by √dk controls dot-product magnitude under the usual independent-component variance intuition. Multiple heads learn separate projections, then concatenate and project their outputs. [Transformer paper]

For a batch of self-attention with B=2, L=5, model width 12 and h=3, each head width is 4. Q/K/V can be arranged as [2,3,5,4]; scores are [2,3,5,5]; concatenated outputs are [2,5,12]. Causal masking disallows future keys; padding masks remove padded keys. In the equation, M is 0 for an allowed key and −∞ for a blocked key. Mask before softmax. An all-masked row needs an explicit convention: the teaching implementation rejects it.

def self_attention(q, k, v, allowed=None):
    """Single head, no batch: Q,K=Lxd_k, V=Lxd_v. True means allowed.

    Requires at least one allowed key per query row. No dropout/projections.
    """
    q, k, v = (np.asarray(a, dtype=float) for a in (q, k, v))
    if (q.ndim != 2 or k.shape != q.shape or v.ndim != 2
            or v.shape[0] != q.shape[0] or min(q.shape) == 0):
        raise ValueError("incompatible self-attention shapes")
    if not all(np.isfinite(a).all() for a in (q, k, v)):
        raise ValueError("inputs must be finite")
    scores = q @ k.T / np.sqrt(q.shape[1])
    if allowed is not None:
        allowed = np.asarray(allowed, dtype=bool)
        if allowed.shape != scores.shape or not allowed.any(axis=1).all():
            raise ValueError("every query needs at least one allowed key")
        scores = np.where(allowed, scores, -np.inf)
    scores -= scores.max(axis=1, keepdims=True)
    weights = np.exp(scores)
    weights /= weights.sum(axis=1, keepdims=True)
    return weights @ v, weights

The implementation omits learned projections, multi-head reshaping, dropout, residuals, and normalization so the core operation stays visible. Directly materialized attention scores use O(L²) memory per head and O(L²d) arithmetic for self-attention; projection work adds O(Ld²). Optimized kernels can change memory behavior without eliminating the dense pairwise arithmetic. Increasing head count at fixed total width does not multiply every cost by head count.

import heapq
import numpy as np


class MatrixSum:
    """Immutable rectangular matrix; inclusive rectangle coordinates."""
    def __init__(self, matrix):
        self.rows = len(matrix)
        self.cols = len(matrix[0]) if self.rows else 0
        if any(len(row) != self.cols for row in matrix):
            raise ValueError("matrix must be rectangular")
        self.prefix = [[0] * (self.cols + 1)
                       for _ in range(self.rows + 1)]
        for r in range(self.rows):
            for c in range(self.cols):
                self.prefix[r + 1][c + 1] = (
                    matrix[r][c] + self.prefix[r][c + 1]
                    + self.prefix[r + 1][c] - self.prefix[r][c]
                )

    def sum(self, r1, c1, r2, c2):
        if not (0 <= r1 <= r2 < self.rows
                and 0 <= c1 <= c2 < self.cols):
            raise ValueError("invalid inclusive rectangle")
        p = self.prefix
        return (p[r2 + 1][c2 + 1] - p[r1][c2 + 1]
                - p[r2 + 1][c1] + p[r1][c1])


def top_k(items, k):
    """Return (ID, finite score) pairs; score descending, earlier ties first.

    Each input occurrence is a candidate. IDs need not be comparable.
    """
    if k < 0:
        raise ValueError("k must be nonnegative")
    if k == 0:
        return []
    heap = []
    for order, (doc_id, score) in enumerate(items):
        if not np.isfinite(score):
            raise ValueError("scores must be finite")
        entry = (score, -order, doc_id)
        if len(heap) < k:
            heapq.heappush(heap, entry)
        elif entry[:2] > heap[0][:2]:
            heapq.heapreplace(heap, entry)
    return [(doc_id, score) for score, _, doc_id
            in sorted(heap, key=lambda e: e[:2], reverse=True)]


def softmax_ce(logits, labels):
    """Mean hard-label CE and dL/dlogits. Finite BxC logits, B>0, C>0."""
    z = np.asarray(logits, dtype=np.float64)
    y = np.asarray(labels)
    if z.ndim != 2 or min(z.shape) == 0 or not np.isfinite(z).all():
        raise ValueError("logits must be a nonempty finite BxC matrix")
    if (y.shape != (z.shape[0],) or y.dtype.kind not in 'iu'
            or (y < 0).any() or (y >= z.shape[1]).any()):
        raise ValueError("one valid integer class index per row required")
    shifted = z - z.max(axis=1, keepdims=True)
    log_probs = shifted - np.log(np.exp(shifted).sum(axis=1, keepdims=True))
    loss = -log_probs[np.arange(len(y)), y].mean()
    grad = np.exp(log_probs)
    grad[np.arange(len(y)), y] -= 1
    grad /= len(y)
    return float(loss), grad


def linear_step(x, y, w, b, lr=0.1, l2=0.0):
    """One SGD step; loss includes l2*||w||^2/2, bias unregularized."""
    loss, dz = softmax_ce(x @ w + b, y)
    dw = x.T @ dz + l2 * w
    db = dz.sum(axis=0)
    objective = loss + 0.5 * l2 * np.sum(w * w)
    return float(objective), w - lr * dw, b - lr * db


def in_batch_loss(q, d, tau=1.0):
    """Q,D: Bxd, matched diagonal pairs; no normalization inside."""
    q, d = np.asarray(q, dtype=float), np.asarray(d, dtype=float)
    if q.ndim != 2 or q.shape != d.shape or not np.isfinite(tau) or tau <= 0:
        raise ValueError("matched Bxd matrices and positive finite tau required")
    loss, ds = softmax_ce(q @ d.T / tau, np.arange(q.shape[0]))
    return loss, ds @ d / tau, ds.T @ q / tau


def self_attention(q, k, v, allowed=None):
    """Single head, no batch: Q,K=Lxd_k, V=Lxd_v. True means allowed.

    Requires at least one allowed key per query row. No dropout/projections.
    """
    q, k, v = (np.asarray(a, dtype=float) for a in (q, k, v))
    if (q.ndim != 2 or k.shape != q.shape or v.ndim != 2
            or v.shape[0] != q.shape[0] or min(q.shape) == 0):
        raise ValueError("incompatible self-attention shapes")
    if not all(np.isfinite(a).all() for a in (q, k, v)):
        raise ValueError("inputs must be finite")
    scores = q @ k.T / np.sqrt(q.shape[1])
    if allowed is not None:
        allowed = np.asarray(allowed, dtype=bool)
        if allowed.shape != scores.shape or not allowed.any(axis=1).all():
            raise ValueError("every query needs at least one allowed key")
        scores = np.where(allowed, scores, -np.inf)
    scores -= scores.max(axis=1, keepdims=True)
    weights = np.exp(scores)
    weights /= weights.sum(axis=1, keepdims=True)
    return weights @ v, weights

def finite_diff(f, a, eps=1e-6):
    g = np.zeros_like(a, dtype=float)
    for index in np.ndindex(a.shape):
        hi, lo = a.copy(), a.copy()
        hi[index] += eps
        lo[index] -= eps
        g[index] = (f(hi) - f(lo)) / (2 * eps)
    return g

class BM25Index:
    """Inverted index with BM25 scoring and incremental add/replace/delete.

    add(doc_id, text)  insert, or replace if doc_id exists
    delete(doc_id)     -> bool (False if absent)
    search(query, k)   -> [(doc_id, score)], score desc, ties by doc_id asc.
                          Only docs matching >= 1 query term. Duplicate query
                          terms count once. Doc ids must be mutually comparable.
    IDF = ln(1 + (N - df + 0.5) / (df + 0.5))   (always positive)
    Complexity: search is O(sum of matched posting lengths + M log(k+1)), plus query analysis.
    """

    def __init__(self, k1=1.2, b=0.75):
        if not math.isfinite(k1) or k1 < 0 or not math.isfinite(b) or not 0 <= b <= 1:
            raise ValueError("require finite k1 >= 0 and 0 <= b <= 1")
        self.k1, self.b = k1, b
        self.postings = defaultdict(dict)  # term -> {doc_id: tf}
        self.doc_len = {}                  # doc_id -> token count
        self.doc_tf = {}                   # doc_id -> Counter, needed for delete
        self.total_len = 0

    def __len__(self):
        return len(self.doc_len)

    def add(self, doc_id, text):
        if doc_id in self.doc_len:
            self.delete(doc_id)
        tf = Counter(tokenize(text))
        for term, count in tf.items():
            self.postings[term][doc_id] = count
        n = sum(tf.values())
        self.doc_len[doc_id] = n
        self.doc_tf[doc_id] = tf
        self.total_len += n

    def delete(self, doc_id):
        tf = self.doc_tf.pop(doc_id, None)
        if tf is None:
            return False
        for term in tf:
            plist = self.postings[term]
            del plist[doc_id]
            if not plist:
                del self.postings[term]
        self.total_len -= self.doc_len.pop(doc_id)
        return True

    def idf(self, term):
        n = len(self.doc_len)
        df = len(self.postings.get(term, ()))
        return math.log(1 + (n - df + 0.5) / (df + 0.5))

    def search(self, query, k=10):
        _check_k(k)
        if k <= 0 or not self.doc_len:
            return []
        avgdl = (self.total_len / len(self.doc_len)) or 1.0
        scores = defaultdict(float)
        for term in set(tokenize(query)):
            plist = self.postings.get(term)
            if not plist:
                continue
            w = self.idf(term)
            for doc_id, f in plist.items():
                norm = self.k1 * (1 - self.b + self.b * self.doc_len[doc_id] / avgdl)
                scores[doc_id] += w * f * (self.k1 + 1) / (f + norm)
        return heapq.nsmallest(k, scores.items(), key=lambda x: (-x[1], x[0]))

def dcg_at_k(grades, k):
    """Nonnegative finite grades; gain=2**grade-1; rank discount=log2(rank+1)."""
    _check_k(k)
    if any(not math.isfinite(g) or g < 0 for g in grades):
        raise ValueError("grades must be finite and nonnegative")
    return sum((2 ** g - 1) / math.log2(i + 2) for i, g in enumerate(grades[:k]))


def ndcg_at_k(ranked_ids, qrels, k):
    """Unique ranked IDs. Unjudged=0 by convention. IDCG uses all qrels.
    Returns None if IDCG=0 (including k=0); caller chooses aggregation policy.
    """
    _check_k(k)
    _unique_ids(ranked_ids)
    idcg = dcg_at_k(sorted(qrels.values(), reverse=True), k)
    if idcg == 0:
        return None
    return dcg_at_k([qrels.get(d, 0) for d in ranked_ids], k) / idcg


def reciprocal_rank(ranked_ids, relevant):
    """1/rank of first relevant doc; 0.0 if none retrieved."""
    for i, d in enumerate(ranked_ids, 1):
        if d in relevant:
            return 1.0 / i
    return 0.0


def recall_at_k(ranked_ids, relevant, k):
    """Recall over known relevant IDs; unique results; None for no relevant IDs."""
    _check_k(k)
    _unique_ids(ranked_ids)
    relevant = set(relevant)
    if not relevant:
        return None
    return len(set(ranked_ids[:k]) & relevant) / len(relevant)

def rrf(ranked_lists, c=60, weights=None, top_n=None):
    """Weighted reciprocal-rank fusion; original 1-based ranks retained.
    Within-list duplicates keep their first rank; ties use comparable ID order.
    """
    if not math.isfinite(c) or c < 0:
        raise ValueError("c must be finite and nonnegative")
    if top_n is not None:
        _check_k(top_n)
    weights = [1.0] * len(ranked_lists) if weights is None else list(weights)
    if len(weights) != len(ranked_lists) or any(not math.isfinite(w) or w < 0 for w in weights):
        raise ValueError("one finite nonnegative weight per list required")
    scores = defaultdict(float)
    for w, lst in zip(weights, ranked_lists):
        seen = set()
        for rank, d in enumerate(lst, 1):
            if d in seen:
                continue
            seen.add(d)
            scores[d] += w / (c + rank)
    out = sorted(scores.items(), key=lambda x: (-x[1], x[0]))
    return out if top_n is None else out[:top_n]

    O(len(prefix) + k) and add() is O(len(phrase) * cache_k log cache_k).
    Invariant holds because weights only increase: a phrase evicted from a
    node's cache can never re-qualify without being re-added on that path.
    Decreases/deletes would need the subtree to recompute caches (or lazy repair).
    """

    def __init__(self, cache_k=10):
        _check_k(cache_k)
        self.root = _TrieNode()
        self.weight = {}
        self.cache_k = cache_k

    def add(self, phrase, delta=1.0):
        if not math.isfinite(delta) or delta <= 0:
            raise ValueError("weights only increase in this contract")
        p = normalize_phrase(phrase)
        if not p:
            raise ValueError("empty phrase")
        w = self.weight.get(p, 0.0) + delta
        self.weight[p] = w
        node = self.root
        self._update(node, p, w)
        for ch in p:
            node = node.children.setdefault(ch, _TrieNode())
            self._update(node, p, w)

    def _update(self, node, p, w):
        top = [e for e in node.top if e[1] != p]
        top.append((-w, p))
        top.sort()
        node.top = top[: self.cache_k]

    def complete(self, prefix, k=5):
        _check_k(k)
        if k > self.cache_k:
            raise ValueError("k exceeds cache_k")
        node = self.root
        for ch in normalize_prefix(prefix):
            node = node.children.get(ch)
            if node is None:
                return []
        return [(p, -nw) for nw, p in node.top[:k]]

def levenshtein(a, b, max_dist=None):
    """Edit distance (insert/delete/substitute = 1). If max_dist is given and the
    distance exceeds it, returns max_dist + 1 early. O(len(a) * len(b)) time,
    O(min) space."""
    if max_dist is not None:
        _check_k(max_dist)
    if len(a) < len(b):
        a, b = b, a
    if max_dist is not None and len(a) - len(b) > max_dist:
        return max_dist + 1
    prev = list(range(len(b) + 1))
    for i, ca in enumerate(a, 1):
        cur = [i] + [0] * len(b)
        for j, cb in enumerate(b, 1):
            cur[j] = min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + (ca != cb))
        if max_dist is not None and min(cur) > max_dist:
            return max_dist + 1
        prev = cur
    d = prev[-1]
    return d if max_dist is None or d <= max_dist else max_dist + 1


def _deletes(word, max_edit):
    """All strings reachable from word by <= max_edit single-char deletions."""
    out, frontier = {word}, {word}
    for _ in range(max_edit):
        frontier = {w[:i] + w[i + 1:] for w in frontier for i in range(len(w))}
        out |= frontier
    return out


class FuzzyLexicon:
    """SymSpell-style candidate generation. Precompute delete-variants of every
    vocab word; at query time, delete-variants of the term hit the table, and
    candidates are verified with bounded Levenshtein.
    Complete for Levenshtein <= max_edit: a substitution is one delete on each
    side, an insertion is one delete on one side.

    lookup(term) -> [(word, dist, freq)] sorted by dist asc, freq desc, word asc.
    """

    def __init__(self, max_edit=2):
        _check_k(max_edit)
        self.max_edit = max_edit
        self.freq = {}
        self.table = defaultdict(set)

    def add(self, word, freq=1):
        word = word.lower()
        if word not in self.freq:
            for v in _deletes(word, self.max_edit):
                self.table[v].add(word)
        self.freq[word] = self.freq.get(word, 0) + freq

    def lookup(self, term, max_edit=None):
        if max_edit is not None:
            _check_k(max_edit)
            if max_edit > self.max_edit:
                raise ValueError("requested radius exceeds indexed radius")
        d = self.max_edit if max_edit is None else max_edit
        term = term.lower()
        cands = set()
        for v in _deletes(term, d):
            cands |= self.table.get(v, set())
        hits = []
        for w in cands:
            dist = levenshtein(term, w, d)
            if dist <= d:
                hits.append((w, dist, self.freq[w]))
        hits.sort(key=lambda x: (x[1], -x[2], x[0]))
        return hits

class Frecency:
    """score(item, t) = sum over past uses t_i <= t of 0.5 ** ((t - t_i) / half_life).
    O(1) per record/score by storing (score at last update, last update time):
        s <- s * exp(-lam * (t - t_last)) + 1,   lam = ln 2 / half_life
    Timestamps per item must be non-decreasing."""

    def __init__(self, half_life):
        if not math.isfinite(half_life) or half_life <= 0:
            raise ValueError("half_life must be positive")
        self.lam = math.log(2) / half_life
        self.state = {}  # item -> (score_at_t_last, t_last)

    def record(self, item, t):
        if not math.isfinite(t):
            raise ValueError("finite timestamp required")
        s, t0 = self.state.get(item, (0.0, t))
        if t < t0:
            raise ValueError("out-of-order timestamp")
        self.state[item] = (s * math.exp(-self.lam * (t - t0)) + 1.0, t)

    def score(self, item, t):
        if not math.isfinite(t):
            raise ValueError("finite timestamp required")
        if item not in self.state:
            return 0.0
        s, t0 = self.state[item]
        if t < t0:
            raise ValueError("query time before last use")
        return s * math.exp(-self.lam * (t - t0))

    def top(self, t, k):
        _check_k(k)
        return heapq.nsmallest(k, ((i, self.score(i, t)) for i in self.state),
                               key=lambda x: (-x[1], x[0]))

def _unit(x):
    x = np.asarray(x, dtype=np.float64)
    if not np.isfinite(x).all():
        raise ValueError("finite vectors required")
    n = np.linalg.norm(x, axis=-1, keepdims=True)
    if np.any(n == 0):
        raise ValueError("zero vector")
    return x / n


def mmr(query_vec, doc_vecs, k, lam=0.7):
    """Maximal marginal relevance with cosine similarity.
    Greedy: argmax_d  lam * sim(q, d) - (1 - lam) * max_{s in selected} sim(d, s).
    Returns indices in selection order; ties -> lower index. O(k * n * dim)."""
    _check_k(k)
    if not math.isfinite(lam) or not 0 <= lam <= 1:
        raise ValueError("lambda must be in [0,1]")
    if k == 0 or len(doc_vecs) == 0:
        return []
    query_vec = np.asarray(query_vec, dtype=np.float64)
    doc_vecs = np.asarray(doc_vecs, dtype=np.float64)
    if query_vec.ndim != 1 or doc_vecs.ndim != 2 or doc_vecs.shape[1] != query_vec.size:
        raise ValueError("a 1D query and compatible 2D document matrix are required")
    q, D = _unit(query_vec), _unit(doc_vecs)
    rel = D @ q
    k = min(k, len(D))
    selected = []
    max_red = np.full(len(D), -np.inf)  # max sim to any selected doc
    avail = np.ones(len(D), dtype=bool)
    for _ in range(k):
        red = np.where(np.isfinite(max_red), max_red, 0.0)
        score = np.where(avail, lam * rel - (1 - lam) * red, -np.inf)
        i = int(np.argmax(score))  # argmax returns first max -> lower index wins
        selected.append(i)
        avail[i] = False
        max_red = np.maximum(max_red, D @ D[i])
    return selected


def pack_context(passages, budget_tokens, overhead_tokens=0, count_tokens=None):
    """Priority-order greedy packing; returns kept IDs, skipping oversized items.

    Requires an explicit token counter for the target model. Candidate contexts
    are serialized as '[ID]\ntext' blocks separated by two newlines, and the
    WHOLE candidate context is counted each time. overhead_tokens optionally
    reserves extra per-item tokens outside that serialization. This budget is
    for evidence only; reserve instructions, history, tools and output first.
    A toy counter may be injected in tests but is not an LLM token guarantee.
    """
    _check_k(budget_tokens)
    _check_k(overhead_tokens)
    if not callable(count_tokens):
        raise ValueError("provide the target model's token counter")
    _unique_ids([pid for pid, _ in passages])
    kept, blocks = [], []
    for pid, text in passages:
        candidate = blocks + [f"[{pid}]\n{text}"]
        count = count_tokens("\n\n".join(candidate))
        _check_k(count)
        if count + overhead_tokens * len(candidate) <= budget_tokens:
            kept.append(pid)
            blocks = candidate
    return kept

def quantize_int8(x):
    """Symmetric per-row quantization: float32 input -> int8 codes + float32 scales.
    x_hat=codes*scales[:,None]. Rounding error <= scale/2, up to float roundoff,
    relative to the float32 input when scale is representable and no clipping.
    Zero rows use scale=1. Not an exact ranking guarantee.
    """
    x = np.atleast_2d(np.asarray(x, dtype=np.float32))
    if x.ndim != 2 or x.shape[1] == 0 or not np.isfinite(x).all():
        raise ValueError("finite vectors with nonzero dimension required")
    maxima = np.abs(x).max(axis=1)
    scales = maxima / 127.0
    if np.any((maxima > 0) & (scales == 0)):
        raise ValueError("quantization scale underflow")
    scales[maxima == 0] = 1.0
    codes = np.clip(np.rint(x / scales[:, None]), -127, 127).astype(np.int8)
    return codes, scales.astype(np.float32)


def top_k_indices(scores, k):
    """Finite 1D scores; descending score, then ascending index.
    Partition + a linear boundary-tie scan + sort of only k chosen entries:
    O(n + k log(k+1)) time and O(n) auxiliary memory in this NumPy version.
    """
    _check_k(k)
    scores = np.asarray(scores, dtype=np.float64)
    if scores.ndim != 1 or not np.isfinite(scores).all():
        raise ValueError("finite 1D scores required")
    k = min(k, len(scores))
    if k == 0:
        return np.array([], dtype=int)
    threshold = np.partition(scores, len(scores) - k)[len(scores) - k]
    above = np.flatnonzero(scores > threshold)
    tied = np.flatnonzero(scores == threshold)[:k - len(above)]
    chosen = np.concatenate((above, tied))
    return chosen[np.lexsort((chosen, -scores[chosen]))]


def int8_search(query, codes, scales, k, block_rows=1024):
    """Exhaustive search using quantized scores, approximate versus float inputs.
    Int32 accumulation is performed in bounded row blocks. This NumPy reference
    widens integers; it is NOT a native optimized int8 SIMD/ANE kernel.
    Work memory: O(block_rows*d + n), excluding input and top-k temporaries.
    """
    _check_k(k)
    _check_k(block_rows)
    q = np.asarray(query, dtype=np.float32)
    codes, scales = np.asarray(codes), np.asarray(scales, dtype=np.float64)
    if (q.ndim != 1 or codes.ndim != 2 or codes.dtype != np.int8
            or q.size == 0 or codes.shape[1] != q.size
            or scales.shape != (len(codes),) or block_rows == 0
            or not np.isfinite(q).all() or not np.isfinite(scales).all()
            or np.any(scales <= 0)):
        raise ValueError("compatible finite query, int8 codes and positive scales required")
    if (codes.size and codes.min() == -128) or q.size * 127 * 127 > np.iinfo(np.int32).max:
        raise ValueError("require [-127,127] codes and int32-safe dimension")
    qc, qs = quantize_int8(q)
    query32 = qc[0].astype(np.int32)
    approx = np.empty(len(codes), dtype=np.float64)
    for start in range(0, len(codes), block_rows):
        end = min(start + block_rows, len(codes))
        raw = codes[start:end].astype(np.int32) @ query32
        approx[start:end] = raw.astype(np.float64) * scales[start:end] * qs[0]
    return top_k_indices(approx, k), approx


def recall_vs_exact(approx_ids, exact_ids):
    """Agreement with float/exact top-k, not relevance recall. None if empty gold."""
    approx, exact = set(np.asarray(approx_ids).tolist()), set(np.asarray(exact_ids).tolist())
    return len(approx & exact) / len(exact) if exact else None

def brute_bm25(docs, query, k1=1.2, b=0.75):
    toks = {d: D.tokenize(t) for d, t in docs.items()}
    n = len(toks)
    avgdl = sum(len(t) for t in toks.values()) / n
    out = {}
    for d, t in toks.items():
        s = 0.0
        for term in set(D.tokenize(query)):
            f = t.count(term)
            if not f:
                continue
            df = sum(term in x for x in toks.values())
            idf = math.log(1 + (n - df + 0.5) / (df + 0.5))
            s += idf * f * (k1 + 1) / (f + k1 * (1 - b + b * len(t) / avgdl))
        if s > 0:
            out[d] = s
    return sorted(out.items(), key=lambda x: (-x[1], x[0]))
